# 2c6a14fe — v4.17.13.0 - Fixed: Guide button virtual key code fixed.

- **Date:** 2020-11-15  |  **Risk (A.1):** HIGH (filename proxy `Options.cs` — false positive, app-local options only)

## Changes

### Fixes
- Guide button press now sends the key(s) configured in `Options.GuideButtonAction`
  (parsed via new `GetGuideKeys()` + regex `{(?<key>[0-9a-zA-Z]+)}`, accepting numeric
  virtual-key codes or `Keys` enum names) instead of hardcoded `LWin+G`.
- Key send no longer marshalled through `ControlsHelper.BeginInvoke` — runs directly
  under `guideLock` on the DInput thread (removes UI-thread dependency/latency).

### Updates
- `GuideButtonAction` default changed `"{LWin}{G}"` → `"{7}"` (virtual key code 7 —
  the actual Guide key code; this default change IS the titled fix).

### Additions
- `GetGuideKeys()` helper + `rxKeys` regex in `DInputHelper.Step5.VirtualDevices.cs`.

### Removals
- Hardcoded `SendDown/SendUp(Keys.LWin, Keys.G)` calls and the `BeginInvoke` wrapper.

## Backward compatibility for 4.17.x
- **Settings.xml wire format:** unaffected (`GuideButtonAction` is an existing string
  option; only its default changes — stored user values still load).
- **WebService API / data model:** unaffected.
- Restored tree verified: `App.v4/Common/DInput/DInputHelper.Step5.VirtualDevices.cs:174-186`
  still has old code; `App.v4/Common/Options.cs:150` still defaults `{LWin}{G}`;
  `Engine/JocysCom/Processes/KeyboardHelper.cs:66` has `SendDown(params Keys[])` — compiles.

## Decision
**Apply.** Path translation: `x360ce.App.Beta/` → `App.v4/`. Skip the ChangeLog hunk.
Apply together with the follow-up parse fix in [f295e72e](f295e72e.md) (case-insensitive
enum parse) as one logical fix.
