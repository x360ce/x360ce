# 1497b94a — Fix internal threading crash when updating UI.

- **Date:** 2021-05-26  |  **Risk (A.1):** MEDIUM
- **Files:** 2 — `IssueItem.cs` (debug trace), `IssuesControl.xaml.cs` (WPF)

## Changes

### Fixes
- The issue checker's `queueTimer_DoWork` runs on a worker thread and called
  `UpdateDisplayedList()` directly, which writes to the list bound to the grid
  and to the status controls. Wrapped in `ControlsHelper.Invoke`.

## Backward compatibility for 4.17.x
The upstream file is the WPF control, but the restored WinForms
`IssuesUserControl` has the identical defect — its own comment on
`queueTimer_DoWork` says "This function will run on different thread than UI.
Make sure to use Invoke for interface update", and it then calls
`UpdateDisplayedList()` inline. `Warnings` is a `BindingListInvoked` with a
synchronizing object, so the grid rows marshal correctly, but
`StatusLabel.Text`, `UpdateIgnoreAllButton()` and `UpdateNoIssuesPanel()` all
touch controls straight from the worker thread.

## Decision
**Partial — applied.** Intent ported to the WinForms control: the whole
`UpdateDisplayedList()` call runs through `ControlsHelper.Invoke`. The WPF
control and the debug `Trace.WriteLine` are not ported.
